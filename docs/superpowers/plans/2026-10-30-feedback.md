# Mori Feedback Implementation Plan

> **For agentic workers:** Use available workers with bounded file ownership and independent review; execute existing TDD and verification skills directly.

**Goal:** Add Toast, Popup and Dialog to Mori with usable demos, real lifecycle behavior and accessibility.

**Architecture:** Keep UTS/uvue and existing theme. Popup owns modal rendering, lifecycle and H5 focus/scroll adaptation; Dialog composes Popup. Toast is a page-local mounted component with imperative show/close plus controlled visibility, timer replacement and cleanup.

**Tech Stack:** Existing Vue/uni-app x/Sass, Node assertions and Playwright. No new runtime dependencies.

## Contracts

- `mori-popup`: boolean v-model; position center/bottom/top/left/right (bottom default); title:string; closable:boolean=true; overlay:boolean=true; closeOnOverlayClick=true; closeOnEscape=true; duration=180; zIndex=1000; safeAreaInsetBottom=true. Default slot. Events update:modelValue, open, opened, close(reason: overlay/escape/close), closed. Parent false closes without emitting a user close request. Retain exit animation, cancel stale timers on reversal/unmount. Explicitly guard hidden/non-top overlays and block overlay propagation. H5 trap/restore focus and reference-count background scroll locking; only the top popup handles Escape. Mount at page root; transformed ancestor limitation and native page-meta requirements documented. Avoid unsupported cross-end teleport in first batch.
- `mori-dialog`: boolean v-model; title,message,confirmText='确认',cancelText='取消',showCancelButton=true,confirmLoading=false,closeOnOverlayClick=false. Compose centered Popup; default slot may replace message. confirm emits only, parent closes (supports async work without races); cancel emits cancel then requests false. Loading prevents duplicate confirm/cancel/escape/overlay closure. Popup close translated once into dialog cancel. Use accessible title and matching role.
- `mori-toast`: modelValue=false,message='',type=text/success/error/loading,duration=2000,position=middle/top/bottom. Exposed `show(options: MoriToastOptions)` restarts timer and replaces current content, `close()` cancels; duration=0 is persistent, loading does not automatically force duration=0. Events update:modelValue,close. One instance per page recommended; repeated show replaces not queues. Show while visible always restarts full countdown. Dismiss on duration/message changes in controlled mode by restarting; manual close, unmount and reopening must invalidate old callbacks. Non-blocking pointer events; status/live region, error alert. Readable inverse palette and Lucide assets already shipped; reduced-motion support for Web spinner/fade. Export options/instance types in feedback.uts.
- H5 modal stack and timer/state helpers in feedback.uts/platform overlay adapter must have one owner. Core components never directly use window/document. Native runtime remains unverified until executed; no global singleton Toast API or promises in this batch.

Toast ownership: show(options) updates local options (omitted options use component prop defaults), displays immediately and emits update:modelValue(true). Parent visibility changes always apply. Parent message/type/duration/position changes replace the corresponding local option and restart countdown while visible. A false->true model acknowledgement of imperative show must not overwrite the just-shown options. close is idempotent and emits false/close once per visible session. Standalone ref usage without v-model is supported; external false can only be observed when the prop actually changes.

Popup stack ownership: every opening allocates effective z-index `max(requestedZIndex, currentTopZIndex + 2)`; newest open is top and visual/focus/Escape use this same order. Custom zIndex is a minimum, not a way to put a newly opened modal below another. Keep stack ownership through exit animation; release only at unmount/closed, and ignore new close requests once model is false. Reversal cancels exit release and stale closed callbacks.
